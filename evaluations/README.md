## What happened

- For the staging-region question, recent selection omitted the older staging approval. The model answered with the production region, `us-east-1`. Relay retained staging evidence and the model returned `eu-west-2` with its correct source label.
- All three modes found the buried loading dock and cited its correct source. This case does not show a retrieval advantage.
- The model found the corrected replacement decision in every mode but included unsupported or extra evidence labels, failing the strict task check.
- The format task returned `plain_text format` instead of the requested exact value `plain_text`. It is counted as a failure rather than normalised into a success after seeing results.
- Every mode answered `unknown` for an unconfirmed arrival date, but the model also cited coverage fields instead of returning the required empty evidence list. These are failures under the specified contract.

Retaining useful information and getting the model to use and cite it correctly are separate problems. The run exposed both a scope-confusion case and a citation-validation gap. A useful next workflow should check cited source IDs against actual available records and test recovery after a rejected or unsupported answer.

## Limits

Five hand-authored fixtures with one small model and one repeat cannot establish general effectiveness, statistical significance, or superiority over existing memory products. This is a selection-policy smoke test; it does not test automated correction extraction or a live tool workflow. No external business actions ran. Token budgets and historical recovery have deterministic API coverage, but this evaluation uses character limits and does not test those new features end to end with the model.

Observed mean wall times were about 35.7s for full history, 14.0s for the recent control, and 9.0s for Relay. These are measurements from this machine and run, **not a speed claim**: there was no warm-up, full history has more input, mode order rotates, and model loading/caching affect timing. Reported token counts are Ollama metrics, not Relay's optional preflight token measurement.

The raw report's general limitation text says retrieval queries repeat target words from requests. The correction fixture also adds `replacement correction`, based on the corrected value already given to all modes in application state. This is fully visible in its prepared inputs and does not demonstrate automatic correction detection.
